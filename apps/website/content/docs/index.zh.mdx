---
title: 介绍
description: 在 cn、clsx、twMerge 的基础上增加 macro 编译。
---

`twl` 提供支持注释模板的 `cn`、`clsx`、`twMerge` 实现，同时导出 `ClassValue`、`ClassNameValue` 参数类型。`twl/macro` 只声明这三个函数的类型，没有运行时导出，由编译器处理。

## 安装

```sh
pnpm add twl
```

## 运行时

```ts
import { cn, clsx, twMerge } from 'twl'

cn('p-2', { 'p-4': true }) // 'p-4'
clsx('p-2', { 'p-4': true }) // 'p-2 p-4'
twMerge('p-2', ['p-4']) // 'p-4'
```

## Macro

```ts
import { cn, clsx, twMerge } from 'twl/macro'

const button = cn`
  // 布局
  inline-flex items-center gap-2
  // 间距
  p-2 p-4
  ${variant}
`

clsx`p-2 p-4` // 'p-2 p-4'：只拼接，不合并冲突
twMerge`p-2 ${['p-4']}` // 'p-4'
cn('p-2', { 'p-4': true }) // 普通函数调用仍可使用
```

三个模板标签都支持折叠空白、移除 token 边界上的 `//` 注释，URL 和任意值中的
`//` 会保留。`cn`、`clsx` 的插值支持对象、数组等 `ClassValue`；`twMerge`
沿用 `ClassNameValue`，支持字符串、嵌套数组和原有的空值，不增加对象参数。

配置打包器插件后，静态模板会变成字符串，`cn` 和 `twMerge` 的冲突合并也在编译期
完成。动态模板只保留必要的运行时调用，普通函数调用仍在运行时执行。
宏入口必须配置编译插件。无需编译时，从 `twl` 导入即可使用运行时模板。

`twl/macro` 只有类型声明，编译产物从 `twl/runtime` 导入 cn 包的原生函数，`twl` 主入口提供模板支持。

## Lint

[`eslint-plugin-twl` 和 `oxlint-plugin-twl`](/zh/docs/lint) 会在每个注释组内排序类名，
并把编译器会拒绝的模板直接在编辑器里报出来。
