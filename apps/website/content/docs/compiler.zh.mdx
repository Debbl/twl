---
title: 编译器
description: 编译器产出什么，以及它拒绝编译什么。
---

把 import 从 `twl` 换成 `twl/macro`，再给你的打包器配上插件，每个 `cls` 和 `tw`
模板都会编译成字面量。

## 产出什么

| 输入                                | 输出                                              |
| ----------------------------------- | ------------------------------------------------- |
| ``cls`flex  items-center` ``        | `"flex items-center"`                             |
| ``cls`flex ${className}` ``         | `` `flex ${__twl_clsx(className)}` ``             |
| ``cls`flex ${a ? 'ring-2' : ''}` `` | `` `flex ${a ? 'ring-2' : ''}` ``                 |
| ``tw`px-2 py-1 px-4` ``             | `"py-1 px-4"` —— 编译期合并完成                   |
| ``tw`px-2 ${override}` ``           | ``__twl_twMerge(`px-2 ${__twl_clsx(override)}`)`` |

插值会被包进 `clsx`，除非静态上已经能证明它是字符串——字符串字面量、模板字面量、
两个分支都是字符串的三元，或者有一侧是字符串的 `+`。运行时对每个插值都会调
`clsx`，所以对象和数组会变成类名列表而不是 `[object Object]`，编译产物必须保持一致。

不含插值的 `tw` 模板会在编译期算完合并。`tw` 写死使用一个固定的 `twMerge`，没有任何
用户可配置的面，所以那时算和运行时算是等价的。

## 拒绝什么

从 `twl/macro` 导入，等于承诺这个模板会被编译掉，所以编译器对任何会破坏这个承诺的
写法都很严格。下面每一条都是带文件和行号的构建错误，而不是悄悄流到运行时：

- 出现在非标签位置的引用，比如 `const f = cls`
- 局部变量遮蔽了这个 import
- `import * as twl from 'twl/macro'`
- 落在 `//` 注释里的插值——它会被丢掉

## 选项

| 选项      | 默认值              |                                                                                                              |
| --------- | ------------------- | ------------------------------------------------------------------------------------------------------------ |
| `from`    | `['twl/macro']`     | 哪些模块说明符里的 `cls` 和 `tw` 会被编译掉。加上 `'twl'` 可以连运行时入口一起编译，代价是失去上面那条保证。 |
| `include` | `/\.[cm]?[jt]sx?$/` | 要编译的文件。`twl/next` 不读这个，它按自己的规则匹配。                                                      |
| `exclude` | `/node_modules/`    | 依赖发布出来时已经是编译过的。                                                                               |
